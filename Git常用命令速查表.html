01配置与初始化

装完 Git 第一件事：留下你的身份信息，否则无法提交。

git config --global user.name "你的名字"

设置全局用户名，会写进每条提交记录。

git config --global user.email "you@example.com"

设置全局邮箱，建议与代码托管平台账号一致。

git config --global init.defaultBranch main

新仓库默认分支名改为 main，避免老式的 master。

git config --list

查看当前所有生效的配置项（含来源文件）。

git config --global --edit

用默认编辑器直接编辑全局配置文件。

git config --global core.editor "code --wait"

把默认编辑器换成 VS Code（写多行提交信息时很有用）。

git config --global alias.st status

设置别名，之后 git st 等同 git status。

git help commit

查看某条命令的完整手册；加 -w 可在浏览器打开。

02创建与克隆

从零开始一个仓库，或把别人的仓库拉下来。

git init

在当前目录初始化一个空仓库，生成隐藏的 .git 目录。

git clone <url>

克隆远程仓库到同名文件夹，并自动配置好 origin。

git clone <url> my-dir

克隆到指定目录名。

git clone --depth 1 <url>

浅克隆，只取最近一次提交，体积小、速度快。

git clone -b dev <url>

克隆后直接切换到 dev 分支。

03提交流程（改 → 加 → 提交）

日常使用频率最高的一组命令，占掉你 80% 的操作。

git status

看哪些文件改了、哪些已暂存、当前在哪个分支。动手前先跑它。

git status -s

精简输出：M 已修改、A 新增、?? 未跟踪。

git add <file>

把指定文件加入暂存区。

git add .

暂存当前目录下所有变更（不含被 .gitignore 忽略的文件）。

git add -A

暂存整个仓库的全部变更，包括新增与删除。

git add -p

交互式逐块选择要暂存的内容，可以把一次大改拆成多个提交。

git commit -m "feat: 描述"

把暂存区内容提交为一个版本。

git commit -am "描述"

跳过 add，直接提交已跟踪文件的修改（新文件无效）。

git commit --amend

修改上一条提交的信息，或把漏掉的文件补进去。仅限未推送

git diff

查看工作区与暂存区的差异 —— 还没 add 的改动。

git diff --staged

查看暂存区与上次提交的差异 —— 即将被提交的内容。

git diff HEAD~1

与上一条提交整体比较，看看这一轮到底改了什么。

04分支与合并

Git 的核心能力。新命令用 switch，老教程里的 checkout 仍然可用。

git branch

列出本地分支，当前分支前有 *。

git branch -a

列出本地 + 远程全部分支。

git branch -d feature/login

删除已合并的分支；未合并需用 -D 强删。

git branch -m old new

重命名分支。

git switch -c feature/login

新建分支并立刻切过去（等价 checkout -b）。

git switch main

切换到已有分支。

git switch -

快速切回上一个分支，两个分支间来回横跳。

git checkout <branch>

老写法，切分支仍然可用；新版 Git 推荐 switch。

git merge feature/login

把目标分支合并进当前分支。

git merge --no-ff dev

强制生成合并提交，保留分支结构，历史更清晰。

git merge --abort

合并冲突时放弃合并，回到动手前的状态。

git rebase main

把当前分支的提交“搬到” main 之后，得到一条直线历史。

git rebase -i HEAD~3

交互式整理最近 3 条提交：合并、改信息、调顺序。慎用于已推送

git rebase --continue

解决冲突并 git add 之后，继续变基；--abort 则放弃。

git cherry-pick <commit-hash>

把别的分支上的某一条提交单独摘到当前分支。

05远程仓库

拉取与推送。团队协作中最容易出问题的地方，先 pull 再 push。

git remote -v

查看已配置的远程地址。

git remote add origin <url>

给本地仓库关联远程仓库。

git remote set-url origin <url>

修改远程地址（换域名、换协议常用）。

git fetch

只下载远程更新，不改动你本地的工作区，最安全的同步方式。

git fetch --prune

顺便清理远程已删除的分支引用。

git pull

等于 fetch + merge，把远程更新合并进当前分支。

git pull --rebase

用变基代替合并拉取，历史是一条直线，团队常用。

git push

推送当前分支到已绑定的上游分支。

git push -u origin main

首次推送并绑定上游分支，之后直接 git push 即可。

git push origin --delete dev

删除远程分支。

git push --force-with-lease

变基后覆盖远程分支的安全写法：远程有新提交时会拒绝。

06撤销与回退

按“改动丢没丢”来选：先想清楚，再敲回车。

git restore <file>

丢弃工作区里某文件的改动，恢复到上次提交的样子。改动丢失

git restore --staged <file>

把文件从暂存区撤下，保留工作区改动。

git reset --soft HEAD~1

撤销最后一次提交，改动全部回到暂存区。最安全的“后悔药”。

git reset HEAD~1

撤销提交并把改动退回工作区（默认 mixed）。

git reset HEAD <file>

只把文件从暂存区撤下，提交历史不动。

git reset --hard HEAD~1

丢弃最后一次提交及其全部改动，无法从工作区找回（可用 reflog 挽救）。

git revert <commit-hash>

生成一条反向提交来抵消某次改动，适合已推送的提交，不动历史。

git clean -n

预览将被删除的未跟踪文件，先看再删，强烈建议养成习惯。

git clean -fd

删除所有未跟踪的文件和目录（新建但没提交的东西会没）。

07查看历史与排查

出问题时最该先用的命令：git log 和 git reflog。

git log --oneline --graph --all --decorate

一条“万能日志”，图形化展示所有分支走向。建议设为别名。

git log -p -2

查看最近 2 条提交的完整改动内容。

git log --stat

每条提交附带改动文件与行数统计。

git log --author="chris"

按作者筛选提交。

git log -S "关键字"

找出哪次提交引入或删除了某段代码，排查 bug 神器。

git log --since="2 weeks ago"

按时间范围过滤提交。

git diff main..dev --stat

对比两个分支的差异概览。

git diff <hash-a> <hash-b>

对比任意两次提交之间的差异。

git diff dev -- src/

只查看某分支中指定目录的变化。

git show <commit-hash>

查看某次提交的详细信息与改动。

git blame <file>

逐行显示谁、在哪次提交改的这行代码。

git reflog

记录 HEAD 的每一次移动。误删分支、reset 错版本都能从这里找回。

git shortlog -sn

按提交数统计贡献者排名。

git fsck --lost-found

极端情况下找回悬空（dangling）提交对象。

08临时存放 stash

活干到一半要切分支，又不想提交 —— 先塞进抽屉。

git stash

把当前未提交的改动存起来，工作区变干净。

git stash -u

连同未跟踪的新文件一起存（默认不含）。

git stash list

查看所有 stash 记录。

git stash pop

取出最近一次 stash 并从列表删除。

git stash apply stash@{1}

取出指定 stash 但在列表中保留副本。

git stash show -p

查看 stash 里具体改了什么。

git stash drop

丢弃最近一次 stash；git stash clear 清空全部。

09标签

给发布点打上标记，比如 v1.0.0。

git tag

列出所有标签。

git tag -a v1.0.0 -m "首个正式版"

创建一个带说明的附注标签（推荐）。

git push origin v1.0.0

推送单个标签到远程；--tags 推送全部。

git tag -d v1.0.0

删除本地标签；删远程需 git push origin --delete v1.0.0。

git switch --detach v1.0.0

临时检出到某个标签版本查看代码。

10忽略与清理文件

不想被 Git 跟踪的东西，交给 .gitignore。

git rm --cached <file>

让文件停止被跟踪，但保留在磁盘上（配合 .gitignore 使用）。

git rm -r --cached .

清空索引后重新 git add .，用于让新写的 .gitignore 整体生效。

git check-ignore -v <file>

查文件为什么被忽略 —— 是哪条规则命中了它。

git update-index --assume-unchanged <file>

临时忽略对某已跟踪文件的本地修改（如本地配置文件）。

git gc --prune=now

压缩仓库、清理无引用的对象，仓库臃肿时用。

11场景速查：我想……

遇到具体问题，直接对着这张表抄。

我想要命令
改上一条提交的说明文字git commit --amend
撤销提交，但改动全部保留git reset --soft HEAD~1
撤销某一文件里还没 add 的改动git restore <file>
撤销一次已经推送的提交git revert <hash>
误删了分支，想找回来git reflog → git switch -c <分支> <hash>
reset --hard 之后发现手滑了git reflog → git reset --hard HEAD@{2}
把别的分支上单独一条提交搬过来git cherry-pick <hash>
提交写错分支了git reset --soft HEAD~1 → 切分支 → 重新 commit
想看某行代码是谁写的git blame <file>
找出某段代码是哪次提交引入的git log -S "关键字"
干活干一半要紧急切分支git stash -u → 切分支 → git stash pop
本地分支比远程落后，想同步git fetch → git rebase origin/main
推送被拒绝（远程有新提交）git pull --rebase → 解决冲突 → git push
想把整个仓库退回某个旧版本git reset --hard <hash>（慎用）或 git revert

12危险命令与铁律

这几条动手前请多看一眼屏幕。

git reset --hard

永久丢弃未提交改动。执行前请确认 git status 干净。

git clean -fdx

连 .gitignore 忽略的文件一起删（比如 .env、本地数据库）。

git push --force

会覆盖远程历史，可能抹掉同事的提交。用 --force-with-lease 替代。

git rebase / commit --amend

对已推送到共享分支的提交使用，会让别人的历史对不上号。

三条铁律：① 动手前先 git status；② 破坏性操作前先 git stash 或建个临时分支；③ 共享分支上只做新增，不改写历史。真出事了，git reflog 通常还能救你。
提交信息建议：用 feat: fix: docs: refactor: chore: 开头，一句话说清“做了什么”。历史读得懂，回滚才敢下手。
